Agent-Mediated Interaction and Shared Legibility

Accessibility has always been machine legibility. The screen reader was the first agent, and everything we learned making interfaces legible to it applies directly to the agents arriving now.

Teams are not struggling because they lack AI tools. They are struggling because the tools cannot see enough of the work to respond with context, and the reason is almost never the model.

Shared context is what makes an agent useful twice

A demo works once, in a clean room, without the messy memory of the organisation attached. What breaks on the second run is not capability. It is that the context was never durable1.

Three things have to be true before an agent can be trusted with a workflow:

  • The sources are in version control, so a claim can be traced to a file.
  • The agent's instructions live beside the material they govern.
  • Review happens before the deploy lane, not after it.

Governance has to live inside the workflow

Governance is not the policy around the tool. It is the shape of the files, permissions, sources, prompts and fallback paths that decide whether the tool can be trusted at all2.

The useful unit is not the prompt. It is the governed knowledge environment around the prompt. From the Anatomy of a Knowledge Base talk

You do not have to adopt a whole stack to get the benefit. Start with the layer that creates the most trust for your own work — usually the one that makes a source checkable.

The move

Stop treating knowledge management as cleanup and start treating it as the operating layer for AI work. The smallest useful step is to pick one high-value workflow with clear source material and test it end to end.
