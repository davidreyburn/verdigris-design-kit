01 / Position

Position

Most design systems publish their palette and ask you to trust it. This one publishes the measurements, including the values that fail — because a contrast claim you cannot check is a decoration, not a commitment.

Three commitments shape everything else. AAA contrast on all text, measured and published, including the values that fail and why they are never used for text. One accent per salience tier, which is the rule that keeps a fifteen-colour ancestry from turning into noise. And every claim testable — the tables on this page are computed from the live tokens, and where a claim turned out to be false it is corrected here in public rather than quietly deleted.

The fifteen-colour ancestry is literal. Verdigris began as a terminal colour scheme, named for the patina on aged copper. This is its translation to the web, which is not a port: a terminal palette solves one problem, telling code apart at a glance, and a web system solves a different one. Only some of the answers carry over.

This page used to open with a fourth: dark only, stated as a position rather than an omission. That position has been retired. There is a paper theme now, and it is not an inversion — on a bone ground every ink accent fails, so the light set is authored rather than flipped. Dark is emitted light; paper is absorbed pigment. Section 02 has both, and section 09 records what is still deliberately absent.

An interface that hides its own decision boundaries has not removed them. It has moved them somewhere you cannot argue with.
02 / Colour

Colour

Measured live from the tokens when this page loaded — the ink set against --vd-ink-000, the paper set against --vd-paper-000. Change a token and these tables change with it. They cannot drift.

Ink — text values, AAA required

Non-text values, 3:1 required

These fail text contrast and are never set as a text colour. Publishing the failures is the point: a table with no failing rows usually means the failing values were quietly left out.

Paper — the light theme, measured against bone

Not an inversion of the ink set. On a bone ground every ink accent fails: lime measures 1.05:1, green 2.13:1, blue 2.12:1. So the paper accents are authored rather than flipped — same hue families, opposite physics. Saturation rises as lightness falls, which is what makes them read as inks rather than as dimmed glows. Hue drift from their ink counterparts is held under 13°, so the families survive the theme change: green 120°→131°, lime 80°→68°, blue 208°→204°, red 0°→0°.

Two consequences worth stating. The first: the focus ring cannot stay lime. At 1.05:1 on bone it would be an invisible focus indicator, which is a conformance failure rather than a matter of taste. It becomes citron, so the rule "the focus ring is the data colour" stays true in both themes.

The second: surfaces move away from the text colour, not downward. The ink ramp's recessed panel is darker because bone text is light, so on paper the recessed panel is lighter. Mirroring the direction instead of the principle put every paper accent below AAA on the sunken surface — fir 6.73:1, citron 6.65:1, slate 6.45:1. That is how the mistake was caught.

Three accents, one per salience tier

An earlier draft capped this at two accents. That was the right instinct expressed as the wrong constraint: counting colours is a crude proxy for "do not make a rainbow". The real discipline is that accents occupy different salience tiers, so they read as a hierarchy instead of as peers competing for the same attention.

TokenFrequencyDistance from groundJob

Distance from ground, not brightness. The earlier wording said data was "maximum salience at 14.68:1", which only means anything on a dark ground — on paper the data colour has to be the darkest thing, not the brightest. Stated as distance, the tier holds in both themes.

Link marks text; structure marks regions. The old rule gave link colour "links and hover affordances", which collided with structure's claim on rules and state the moment a hover affordance was a rule. Drawing the line by what is being marked resolves it.

A nav item hovers in link colour because it is link text, while its active indicator is structure colour because that is the item's state. A card hovers in structure colour throughout, because the whole region is the target and its title is not set in link colour.

The data rule is enforced in code rather than by discipline: vd-system-card tests each proof value and only grants the data colour to one that starts with a digit. Grades like AAA take --vd-text-strong instead — they are not measurements, and a non-numeric value in the data colour has no carrying channel. See section 07 for what that means.

04 / Rhythm

Rhythm

Baseline-derived. Every vertical measurement is a multiple or a half of one line of body text. Body sets 16px over 30px leading, so the unit is 30.

The calibration answer was 16px over 1.85, which gives 29.6px. That is not a number you can build a grid on, so it was tuned to a round 30 (1.875). The deviation is recorded here rather than silently absorbed.

06 / Signature element

topolang

The hero field is not a decorative canvas effect. It is Drift, rendered by a conformant browser runtime for topolang v1.3.2 — a language I wrote and specified — drawing a warped fractional Brownian motion field through the SHADE character mode over a palette authored for this site.

The noise primitives are bit-exact ports of the normative arithmetic and the fixed pipeline is implemented in order. The spec publishes a conformance vector, so the claim is testable rather than asserted. This runs when you load the page:

Live conformance run
Running…

One character mode, at every width

Earlier versions switched modes at 860px — STRATA contour lines on desktop, SHADE below. SHADE now runs everywhere. It reads as dithered relief rather than line-work, which is quieter and far more legible where the display line crosses the field, and the line is now meant to cross it.

There is a consequence worth naming: SHADE is defined with cfn: null, so the contour pass never runs, which means there is no contour colour anywhere on this site. The contourColor on each palette is dead configuration, kept only so the palettes keep the shape the spec describes. The layout still changes at 860px — the field stops being a masked background and becomes a band above the display line, in its own grid row, where no text can be over it — but the mode does not.

The caption on the home page no longer names the mode; a credit line that also tries to be a spec sheet is neither. The runtime still fills any element marked data-topo-mode with whichever mode is actually live, so a caption can never claim STRATA while SHADE is on screen. This page is now that hook's only consumer.

Motion, measured

The field travels right to left at about 13 cells per second, crossing a 174-column hero in roughly thirteen seconds. Earlier values ran 15 to 91 cells per second — the top of that range crossed the hero in under two seconds, which is a gale rather than a drift.

Two faults were fixed together, and they had been masking each other. The offsets were being passed as warpedFbm's own dx/dy parameters, and that function feeds dx into the warp at full weight but into the final sample at 0.6 — so one change was two different translations fought out against each other, and the field deformed in place instead of sliding. Cross-correlating frames two seconds apart and finding the best-matching shift:

Driving the offset viaShiftCoherence
warpedFbm's dx parameter −6 0.943, decaying to 0.669 by 16s
the x argument −9 1.000, holding to 8s

Coherence 1.000 is not luck: shifting the x argument shifts the entire composite function, warp included, so it is a rigid translation by construction. It also travels 1.5× further per unit of drift, carrying a coefficient of 1 rather than 0.6. warpedFbm itself is untouched — the change is which arguments the renderer passes, which is the sketch's business, not the spec's. The second fault was a sign error: a rising offset slides features left, so the heading is 0, not π.

A separate, much slower accumulator drives terrain evolution, so the field is not a rigid photograph sliding past. It is deliberately tiny — 0.0002 per frame holds coherence at 0.992 over eight seconds, 0.0010 drops it to 0.853 — so it buys weather without spending the sense of travel.

Two things worth stating plainly

A discrepancy in my own spec. The canonical example traces colorSlot = 3 for elevation 0.30, justified as "0.12, 0.22, 0.30 are all ≤ 0.30". But 0.30 is the elevation, not a threshold; the third threshold is 0.32. By the normative rule the value is 2. It does not affect conformance, because the contour pass overwrites the slot and the published vector still matches, but the prose needs a correction in v1.3.3.

A guarantee that moved. The bands used to be luminance-capped at source, so the field was safe under text at any opacity — and too faint to be worth rendering. The cap now lives in the mask instead. It holds the field to an effective 0.28 alpha in ink and 0.27 on paper across the text column, and only reaches full alpha past it, where no text sits.

The bands are consequently not safe at full alpha: the darkest paper band alone is 1.40:1 under ink. That is fine, because the mask guarantees text never meets it — but it means the ramp and the mask alpha are now a matched pair. Change one without the other and the guarantee is gone.

Density is a compensation, not a preference. SHADE's fill set is [' ', ' ', '.', '.', '+', '+', '#', '@'] — slots 0 and 1 are spaces, so a quarter of the elevation range renders as nothing by definition, and a gamma above 1 pushes values down into exactly those two slots. Measured over 30 seconds of real drift at the old gamma of 1.7: 36.7% of cells blank.

The clean fix would be a fill set with one blank slot instead of two. But SHADE is spec-defined, and editing it would cost the conformance claim for a cosmetic gain. So gamma dropped to 1.15 and the sketch lifts the whole range off a floor of 0.14 instead — 9% blank, with a far more even distribution across the glyph slots. Valleys survive; holes do not.

07 / Accessibility

Accessibility

Target is WCAG 2.2 AAA for text, on a dark generative site. The measurements are in section 02 and they are taken from the live tokens.

The generative field

The canvas is aria-hidden, because it carries no information a reader needs and describing a drifting noise field to a screen reader is noise, not access. Its provenance is in the visible caption instead, where it is available to everyone.

The field does run under the display line — that is deliberate — and the mask is what keeps it conformant. It holds the field to a capped alpha across the text column and only reaches full strength past it. The mask is a contrast constraint, not a stylistic one, and it is load-bearing in both themes. Compositing the most extreme cell each palette can produce, at the held alpha, over its own ground:

ThemeWorst compositeDisplayBodyMuted

paper — held 0.27 × canvas 1.0 = 0.270 #C1BFB7 9.81 7.75 5.40
† below the 7:1 AAA threshold

The muted value fails in both themes, which is why the hero promotes its sub-line and its caption one step: nothing inside the hero may use the muted text value. That is a rule about one component, stated rather than left to be rediscovered.

These alphas were lowered deliberately after the field's density went up. Until then the measured worst case sat well above the arithmetic floor, because the extreme band rarely landed inside the text column — 9.78:1 measured against a 7.51 floor in ink. Making the field denser made that band commonplace and the measured worst collapsed onto the floor: 7.55:1 in ink, and 7.06:1 on paper with six hundredths of margin. Still conformant, but the buffer had been luck rather than design, so it was bought back on purpose.

Colour vision, measured

Contrast ratios are measured on rendered colour, and WCAG does not simulate colour vision deficiency, so the AAA claim above stands whatever this section says. It is here because the ratios are supposed to buy a hierarchy, and a hierarchy that dissolves for one reader in twelve has not been delivered. Simulated with the Viénot 1999 dichromat matrices, applied in linear RGB:

structure ↔ data40° 0.4°0.3° size and position — both are mono tabular numerals, so hue does nothing. The card index is 12px in an uppercase kicker row; the proof figures are 12px below a rule, 330px away.

The rule, stated so it can be checked. Any two tokens carrying different meanings in the same context must separate after dichromat simulation — 20° of hue or 3:1 of value — and where colour cannot do it, a named non-colour channel must, and is named above.

An earlier version of this page claimed green and lime "stay distinguishable under deuteranopia, where hue alone would fail". Measured, that is false: they simulate to the same hue, 0.4° apart.

The absolute form of the rule turned out to be unsatisfiable by any chromatic palette on a dark ground. Every accent is AAA against the same ground, which compresses their mutual ratios to 1–2:1, and two of three dichromat axes collapse hue to a single yellow–blue opposition — so at most one accent can sit on the blue side.

Sweeping 115°–185° at AAA on --vd-ink-000, the flip lands between 160° and 165°: no structure hue is far from both lime and blue. Structure picks a side. Green picks the yellow side, which separates it from link blue and collides it with data.

Reachable pairs

An accent over --vd-surface-selected measures 5.6–5.9:1 on paper and 5.5–5.7:1 in ink, and that state cannot occur: selection forces the maximum text value, and the only other use of that surface is a collapsed redaction, which sets the text transparent. The same holds for the raised surface, where the two rules that use it set either the maximum or the primary text value. Combinations that are unreachable by construction are listed as such rather than tested, because testing them proves nothing.

Reduced motion

Not "everything stops". The field freezes to a single deterministic seeded frame, so it is still generative and still rendered by the DSL, just not advancing. The same seed always produces the same frame. topolang v1.3.2 requires runtimes to expose exactly this. Rule-draw hovers resolve to a static underline at reduced opacity, because a hover affordance that vanishes entirely is a usability regression.

The setting is honoured live. Flipping it in the OS reconfigures the field without a reload.

Agent legibility

Every component is light DOM and upgrades markup that is already valid and semantic without JavaScript. The page carries JSON-LD, real landmarks, and a heading order that matches its visual order. The argument is that a browsing agent and a screen reader want the same thing, and that treating them as one requirement is cheaper and more honest than treating them as two.

Reflow, measured

WCAG 1.4.10 requires content to reflow at 320 CSS pixels, which is what 400% zoom on a 1280px screen produces. Tested by loading this site in a 320px iframe, because constraining an element does not fire media queries and a resized window on a scaled display does not either. Result: document scroll width 305px against a 305px viewport. No horizontal scrolling.

It failed the first time. The navigation was the single offending element in the whole page: a non-wrapping flex row inside a fixed 60px bar cannot reflow no matter what the viewport does. That is recorded here rather than quietly fixed, because the useful part of an audit is what it caught.

Target size, measured

WCAG 2.5.8 (AA) requires 24×24 CSS pixels. Every target passes. WCAG 2.5.5 (AAA) requires 44×44, and that is met for every standalone control: navigation, masthead, tags, table-of-contents entries, buttons and the copy control.

Heading links used to be a stated deviation. They are not any more. System-card and note-card titles sit at 30px, and the two ways of reaching 44 were both rejected: 45px leading on 18px type wrecks a two-line title, and a stretched overlay link breaks text selection across the card.

The card itself is the target instead — far past 44×44 — with the click forwarded in script under three guards: a press that moved more than 6px was a drag, a non-empty selection means the reader is highlighting, and a target inside another interactive element handles itself. So the prose stays selectable and no overlay exists.

The anchor remains the only focusable thing in the card. No tabindex, no role="link" on the region — that would announce the same destination twice — and :focus-within carries the visual state so keyboard and pointer get the identical affordance. Modifier keys survive because the event is re-dispatched rather than synthesised, so ctrl and cmd click still open a tab.

One gap, stated rather than papered over: middle-clicking the card body does not open a tab, because that is browser behaviour attached to a real anchor hit and cannot be synthesised. Middle-clicking the title works.

Inline links in prose are exempt under 2.5.8 and are left alone. The claim is therefore AA on every target and AAA on every standalone control and card.

Still missing

Screen-reader transcripts, and the other known gaps, are listed together in §09 rather than split across two sections.

Editors and frameworks can read the element API from custom-elements.json at the repository root — a Custom Elements Manifest covering all fourteen elements, their attributes and their events. Nine are registered custom elements; five (vd-nav, vd-footer, vd-quote, vd-figure, vd-meta) are CSS-only styling hooks with no JS, and were missing from the manifest until v1.8.0 — the check that it "matched exactly" had compared it against the registered elements only, so it could not have found them. It is hand-authored; see §09 for why.

Do not start from scratch. template.html uses every major element once with the reasoning beside it; reader.html and resume.html are the two page shapes. §11 records what each one decided.

Tailwind is deliberately absent. A hand-authored system is the argument this site is making, and utility classes would undercut it.

The theme control is an empty element that the script upgrades: <vd-theme-toggle></vd-theme-toggle>. With script off it renders nothing and prefers-color-scheme still selects the theme, which is why it is not a <button> in the markup — a control that cannot work should not be advertised. A stored choice overrides the OS in both directions, on specificity alone, with no !important anywhere.

09 / Non-goals

Non-goals

Measured against a general-purpose enterprise design system, this one has gaps. Most of them are decisions. Listing them is cheaper than being asked, and an unacknowledged gap reads as an oversight where a stated one reads as scope.

Not built, on purpose

AbsentWhy
Framework adapters for React, Vue, Svelte React 19 consumes custom elements without a wrapper, so three published packages would triple the maintained surface and guarantee behavioural drift — which would mean auditing accessibility three times per component, forever. The substitute now exists: custom-elements.json, one artifact consumed by every editor and framework, and the same machine-legibility argument this system already makes about screen readers. It is hand-authored, because adding an analyzer would put npm and a build step into a project that has neither — so it carries a checkedAgainst field recording when it was last verified against the source, since a hand-written manifest can drift and a generated one cannot.
A published Figma or Penpot kit The tokens live in CSS with their measured ratios in comments beside them. A design tool cannot hold that, so a kit would either drop the measurements or become a second source of truth to keep in sync. This page is the reference.
A bidirectional token pipeline Same reason inverted: moving the source of truth into a hosted file would take it out of version control and away from the place the contrast numbers are computed and enforced. A one-way DTCG export is the ceiling here.
Dropdown menus, tabs, pagination, breadcrumbs Nothing in this site needs them, and a four-item nav does not want full ARIA menu semantics. Speculative primitives rot.
A working contact form The form kit in §10 is built and the form is not, which looks like the contradiction of the row above and is worth separating rather than glossing. A speculative primitive is one built against an imagined future requirement, and it rots because nothing exercises it and no one notices when it breaks. The form kit is built against a stated present one: it is the specimen that carries §10's argument about the success colour, and that argument cannot be made in prose alone. It is exercised every time the page is opened. What is absent is the endpoint — submitting anywhere needs a third-party service, which is a runtime dependency this site does not have and does not currently need.
A modal dialog Confirmations, errors and disclosures resolve inline. That is more accessible, and it is consistent with the argument that an interface hiding its decision boundaries has not removed them — an inline confirmation is a visible boundary.

Known limits of what is built

Screen-reader transcripts have not been recorded — that needs NVDA or VoiceOver driven by hand and cannot be automated honestly. Middle-clicking a card body does not open a tab. The field's seed is fixed, so every visitor sees the same sequence at the same moment. And the metadata strip is single-line by design: it changes form below 860px rather than wrapping, because wrapping it leaves a rule hanging in space.

What this page is not. It documents one site's system. It is published as a portfolio piece — evidence of how the decisions were made and what they cost — rather than as a dependency for anyone else to install. If that changes, most of the table above becomes debt rather than scope, and it should be re-read in that light.

10 / Forms

Forms and feedback

Every control below is live. Submit the form with it empty, or type a bad address and tab away — the states are the real ones, driven by the browser's own Constraint Validation API with the native bubble replaced.

Blue is the only hue that clears both axes — and it is already the link colour. So --vd-ok aliases --vd-link, and the collision is paid for rather than denied. A success line is separated from a real link by two things, both required: it carries a glyph, and it is not underlined.

Which is why inline links are underlined now, and were not before. That change was overdue on its own: a link identified by colour alone needs 3:1 against the surrounding text under WCAG G183, and measured, link-against-body is 1.51:1 in ink and 1.67:1 on paper. It was a 1.4.1 failure independent of forms. Components that already carry a non-colour channel — the nav, card titles, buttons, the table of contents — opt out.

Warning carries no hue at all. Orange is 5.77:1, a non-text value, so a warning message could not be orange without breaking the AAA commitment. Inventing a fourth accent to say "careful" was not worth a fourth accent. The glyph and the wording carry it, and --vd-warn resolves to the ordinary text colour — named, so that it is a decision rather than an omission.

11 / Documents

Documents

A design system whose remaining pages were both mostly prose had no opinion about prose. Thirteen base elements were unstyled, and the only list rules in the stylesheet were for navigation — a list inside a paragraph had never been rendered.

A bare image was breaking a published claim

Only vd-figure img set max-width. An author writing a case study and typing <img> pushed the document past the viewport: a 900px screenshot in a 320px column is a 1.4.10 failure on a page whose sibling advertises the opposite. The reflow guarantee rested on every author remembering to reach for a component.

Bare images are now constrained. That is a conformance fix, not a style — no border and no radius, because framing was never the job.

vd-figure lost its frame

This component had zero uses on any page until Calibration 06, so its border and its editorial caption rule had never actually been looked at. Rendered for the first time, both were wrong: a screenshot with its own edges got a double frame, and a caption is a label rather than the page speaking in another voice.

That narrows the editorial family. Section 02 gave patina teal to pull-quotes, figure captions and marginalia. Captions are out; teal now marks the pull-quote, .vd-marginalia and .vd-cite. What distinguishes vd-figure from a bare image is the caption, not the box.

List markers are punctuation, not signal

A stated exception to the ordinal rule. Doctrine says an ordinal is structure and takes green — card indices and section numbers do. A list marker is also an ordinal, but frequency changes what a colour means: a fifteen-item list would put more green on screen than the rest of the page combined, and the accent works by being rare. So the marker is muted and the exception is recorded rather than absorbed.

The marker hangs outside the measure, so list text stays flush with the paragraphs above and below — a list does not indent the article. Ordered lists use zero-padded tabular numerals in the mono face, matching the card indices, so 9 and 10 align.

There is no margin between items, and that is the baseline grid rather than a taste call. --vd-space-h is half a line: with it, ten of twenty-three elements measured 15px off the 30px grid. The published spacing rule permits halves, so it was legal — but the rhythm demo one section up shows lines landing on a shared grid, and a half-step would have made that false for lists. The hanging marker supplies the separation instead.

Two quotations, two devices

vd-quote is a pull-quote: your own line, lifted out, in the editorial colour. A bare <blockquote> is someone else's words, and is deliberately quieter — indent and a hairline, no teal, no size change. If they looked the same, teal would stop being rare.

Print, finally exercised

print.css had existed for several versions without ever being run against a document where print was the point. Page-break control was entirely unset: no orphans, no widows, nothing stopping a role from splitting across a page or a caption from stranding on the sheet after its image. All now set.

One page-scoped exception, stated because it looks like an oversight otherwise: the resume does not print link destinations. Everywhere else it does, on the reasoning that a printed underline pointing nowhere is useless — which still holds for an article's citations. On a resume every bullet would carry a URL and the page becomes unreadable, which is the opposite of the goal.
